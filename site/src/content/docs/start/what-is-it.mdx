BackendKit Agent Framework is a TypeScript framework for **enterprise agents**: the agents a business deploys on real systems and has to answer for. General-purpose agent frameworks compete on what an agent can do. This one is built around what a company needs before it lets an agent run: to know what a call can do before it runs, to decide outside the model, to survive a crash, to account for what happened and what it cost, and to change only with a person's approval.

- **Tools, two ways.** Define a tool once and run it driven by a model, or call it directly and deterministically.
- **Governance outside the model.** Policy, approval and audit decide which calls may run, so a destructive call waits for a person.
- **Orchestration.** Agents delegate to each other, or you declare the path as a durable flow that survives a crash and waits for a person.
- **Multitasking.** Flow steps run in parallel by dependency, read-only calls of one turn run together, many runs share a concurrency limit, and autonomous agents work on cron, webhook and event triggers.
- **Self-learning.** Repeated failures become lessons in an agent's prompt and proposed rules that a person approves. An agent cannot approve what it learned.
- **Testable offline.** Scripted models and mock servers, so checks need no API key.

## What makes it for enterprise agents

| A company needs | The framework gives |
|---|---|
| To know what a call can do before it runs | Tools declare facts (`readOnly`, `destructive`, `idempotent`); a tool that says nothing is asked about |
| A decision the model cannot change | Policy, approval and audit are engine configuration; the model cannot approve its own work |
| Work that survives failure | Durable flows with a journal, resumable mid-approval, on files, Redis, SQLite or Postgres |
| To answer for what happened | A tamper-evident audit log with who approved each call, and the cost of each run |
| Spend that stops | Budgets per run and per day with a hard stop |
| Change under control | Lessons and rules proposed from failures; a person approves, an agent cannot |
| Proof before production | Agent logic and failures tested offline, with no API key |

It is a library you embed in your own services, not a hosted platform.

The center is `@backendkit-labs/agent-core`: an **engine** that runs a model in a loop, calling the tools you define, with the governance layer around it.

## The shape of an agent

<EngineLoop />

Three ideas carry most of the framework:

1. **Tools declare facts.** A tool says whether it is `readOnly` or `destructive`. The engine decides what to do with that: a read-only tool runs, a destructive one asks a person. Forgetting to declare asks more, never less. A tool also runs two ways: **LLM-controlled**, when the model decides to call it, or **deterministic**, called directly with exact arguments from your code or an MCP client and no model in between ([both](../../concepts/engine-and-tools/#one-tool-two-ways-to-run-it)).
2. **Governance is outside the model.** The policy, the approver and the audit sink are configuration of the engine. A model cannot talk its way past them.
3. **Work that matters is durable.** A *flow* is data (YAML): steps, dependencies, approvals. It is journalled, so a crash, a deploy or a night's wait does not lose it, and running it again resumes where it stopped.

## The packages

| Package | Use it for |
|---|---|
| `@backendkit-labs/agent-core` | The engine, tools, governance, flows, memory, MCP. Everything starts here. |
| `@backendkit-labs/agent-providers` | The model: OpenAI-compatible APIs (OpenAI, DeepSeek, Ollama) and Anthropic. |
| `@backendkit-labs/agent-testkit` | Tests with no API key: a scripted provider, a mock transport, a mock LLM server. |
| `@backendkit-labs/agent-flow-queue` | Flows across processes: steps on BullMQ workers, runs in Redis. |
| `@backendkit-labs/agent-flow-sql` | Flows that survive restarts on SQLite or Postgres: the run journal in a database. |
| `@backendkit-labs/agent-sandbox` | Confining what agents run. |
| `@backendkit-labs/mcp-server`, `agent-protocol`, `agent-web` | Serving agents to other programs and to browsers. |
| `create-bk-agent` | The project scaffolder. |

Each has its own page under **Packages**.

## What it is not

- It is not a hosted product or a no-code builder. It is a library you import.
- It does not pick your model. Providers are swappable and the engine works with any that implements one small interface.
- It does not make a weak model smart. It makes what a model does *safe, observable and testable*.
