This is the path most people actually want: a multi-agent project that starts small and grows as you need it, using the CLI for both.

## 1. Scaffold

```bash
npx create-bk-agent support-bot
```

You'll be prompted in order — here's a real run, answering for a support bot with two specialists:

## 2. Run it

```bash
cd support-bot
cp .env.example .env
# edit .env — add your ANTHROPIC_API_KEY
npm run dev
```

You now have `orchestrator` + `specialist-a` + `specialist-b` — see [Agent Types § Multi-agent](/getting-started/agent-types) for exactly what those three files contain. They're generic placeholders (`TODO: describe what this specialist does`) — talk to it once to confirm the loop works, then move to shaping it.

## 3. Grow it — replace the placeholder specialists

Don't hand-edit `src/agents/specialist-a.ts` in place; add real ones with the CLI and delete the placeholders once they're wired:

```bash
npx create-bk-agent add specialist billing
```

```
✓  Created src/agents/billing.ts
✓  Patched src/engine.ts  (agents.register(BILLING_PROFILE))

  Reminder: add 'billing' to orchestrator.ts delegatesTo[] and update the systemPrompt.

Next steps:
   Implement src/agents/billing.ts
   npm run dev
```

This isn't just a file template — it patches `engine.ts` for you (adds the import, finds the `// TODO: register more specialists` marker or falls back to inserting after the last `agents.register(...)` call). It does **not** auto-wire delegation — you still have to add `'billing'` to the orchestrator's `delegatesTo` array and mention it in the system prompt, which the reminder tells you.

Repeat for a second specialist:

```bash
npx create-bk-agent add specialist refunds
```

## 4. Give a specialist real tools

```bash
npx create-bk-agent add tools stripe
```

```
✓  Created src/tools/stripe-tools.ts
✓  Patched src/engine.ts  (tools.register(stripeAction, stripeQuery))

Next steps:
   Implement src/tools/stripe-tools.ts
   npm run dev
```

Generates two `defineTool` stubs (`stripe_action`, `stripe_query`) with the Zod schema wiring already correct — replace the `// TODO: implement` bodies with real Stripe SDK calls, then add `'stripe_action'`/`'stripe_query'` to whichever specialist's `allowedTools` should have them.

<Note>
  The console line above is the CLI's own summary text, shown verbatim — what actually lands in `engine.ts` is chained, not comma-separated: `tools.register(stripeAction).register(stripeQuery);`.
</Note>

## 5. Point it at a knowledge base (optional)

```bash
npx create-bk-agent add knowledge ./docs
```

Wires RAG search over a folder — for an `enterprise`-architecture project, or any project where a specialist should answer from real documentation instead of just its system prompt.

## 6. Deploy it as an MCP server

You picked **Terminal REPL** in step 1 to iterate quickly. Once `support-bot` is stable and something else (Director, another agent) needs to call it:

```bash
npx create-bk-agent add server --port 4000
```

```
✓  Created src/server.ts   (HTTP MCP on port 4000)
✓  package.json            (@backendkit-labs/mcp-server added)
✓  package.json            (script "server" added)

Next steps:
   npm install
   npm run server        # starts HTTP MCP on port 4000
```

This is the same [`AgentMCPServer`](/packages/mcp-server) pattern — you get it without hand-writing it. Connect the running server to any other `AgentEngine` as an `mcpServers` entry — see [MCP Integration](/concepts/mcp-integration).

<Tip>
  Picked **MCP Server (stdio)** back in step 1 instead of REPL? You already have `src/server.ts` — skip step 6 entirely, it's already there.
</Tip>

## What you didn't have to do

Hand-write an `AgentProfile`, hand-patch `engine.ts`'s registry calls, hand-write a `defineTool` Zod schema, or hand-compose an `AgentMCPServer`. Every `add` module exists because that boilerplate is exactly what [`packages/templates`](/getting-started/agent-types) already generates once — the CLI just does it again, correctly, every time you need one more.
