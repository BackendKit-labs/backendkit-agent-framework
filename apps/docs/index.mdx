BackendKit is a TypeScript monorepo built around one idea: **the engine that talks to an LLM, runs tools, and delegates to specialists should not know anything about your domain.** Whether you're building a coding assistant, an autonomous ops agent, or a finance department's specialist team, the same `AgentEngine` underneath assembles agents, tools, providers, memory, and orchestration the same way.

## The SDK, at a glance

| Package | Status | What it does |
|---|---|---|
| [`@backendkit-labs/agent-core`](/packages/agent-core) | **core** | The generic engine — model-agnostic, transport-agnostic |
| [`@backendkit-labs/agent-enterprise`](/packages/agent-enterprise) | **core** | RAG + vault writing for enterprise / department-scoped deployments |
| [`@backendkit-labs/agent-coding`](/packages/agent-coding) | **stable** | 10 builtin coding specialists, file tools, git integration, LLM providers |
| `@backendkit-labs/agent-web` | **stable** | HTTP/WebSocket server layer — sessions, triggers, monitoring |
| [`@backendkit-labs/orchestrator-agent`](/packages/orchestrator-agent) | **stable** | Config-driven task decomposition — an LLM (or a static YAML shortcut) breaks one task into a DAG of subtasks |
| `@backendkit-labs/mcp-connectors` | **stable** | HubSpot, Jira, Google Calendar, Odoo, and vault-search MCP connectors |

<Note>
  **Status matters.** `core` packages are reviewed before any change; `stable` packages work and are maintained but won't expand during the pilot phase; `experimental` packages are frozen and may change based on pilot usage. Check a package's guide for its current status before depending on it.
</Note>

## Why one engine, not one engine per use case

A recurring theme in this codebase: **don't build a second orchestration engine when the first one just needs a small, additive extension.** The `Orchestrator`'s gate system was recently generalized to support open-ended, named gates (not just the three built-in `architecture`/`security`/`qa` reviews) — because a finance or HR vertical needs its own gate names, not a fork of the orchestrator. See [Orchestrator](/concepts/orchestrator) for how that works.
