[`@backendkit-labs/agent-enterprise`](/packages/agent-enterprise)'s `createEnterpriseSetup` ships six fixed departments — `general`/`support`/`hr`/`sales`/`finance`/`ops` — and marketing isn't one of them. Rather than force this example into `extraProfiles` (which only gets the *global*, unscoped `search_knowledge` tool — see [agent-enterprise § Adding a custom profile](/packages/agent-enterprise#adding-a-custom-profile)), this page builds a `marketing/`-scoped search tool directly from the same primitives `createEnterpriseSetup` itself uses internally: `ObsidianRAGProvider` and `VaultWriter`, both exported from `agent-enterprise`.

## The vault

```
/obsidian-vault
├── general/            ← shared across the whole org, if you have other agents on the same vault
└── marketing/
    ├── brand-guidelines.md
    ├── campaigns/
    │   ├── q3-launch-brief.md
    │   └── q2-retro.md
    └── competitor-notes.md
```

## A scoped search tool

`ObsidianRAGProvider.createTool()` always names its tool `search_knowledge` — that's the single-tool, whole-vault case `agent-enterprise`'s `general` profile uses. For a named, folder-scoped tool, wrap `.search()` in `defineTool` yourself — this is exactly what `createEnterpriseSetup` does internally for each of its six departments:

```ts src/knowledge.ts
import { ObsidianRAGProvider, VaultWriter, SimpleEmbedder } from '@backendkit-labs/agent-enterprise';
import { defineTool, z } from '@backendkit-labs/agent-core';
import * as path from 'path';
import * as os from 'os';

const vaultPath = process.env.VAULT_PATH ?? '/shared/obsidian-vault';
const indexDir  = path.join(os.homedir(), '.marketing-agent', 'rag');

export const marketingRAG = new ObsidianRAGProvider({
  vaultPath,
  folders: ['marketing', 'general'],
  indexPath: path.join(indexDir, 'marketing.json'),
  embedder: new SimpleEmbedder(),   // deterministic, no Ollama required — swap for OllamaEmbedder for real semantic search
  topK: 5,
  minScore: 0.2,
});

export const searchMarketingKb = defineTool({
  name: 'search_marketing_kb',
  description: 'Search brand guidelines and past campaign briefs in the marketing knowledge base.',
  input: z.object({ query: z.string().describe('What to search for') }),
  execute: async ({ query }) => marketingRAG.search(query),
});

const writer = new VaultWriter({ vaultPath });
export const writeKnowledge = writer.createTool('marketing-lead');   // bakes the writer's agent ID into the tool for the audit trail
```

`indexAll` isn't a method on `ObsidianRAGProvider` directly (that's `createEnterpriseSetup`'s convenience wrapper over several providers) — call `.index()` once at startup instead:

```ts src/index.ts (excerpt)
import { marketingRAG } from './knowledge';

await marketingRAG.index({ verbose: true });   // incremental — only re-embeds new/changed files
```

## Wiring it into the roster

`seoAnalyst` gets read access (it's the one doing research); `copywriter` gets both read and write, so it can check brand guidelines before drafting and save a new campaign learning back to the vault when asked:

```ts src/agents.ts (excerpt)
export const copywriter: AgentProfile = {
  // ...same as step 3
  allowedTools: ['draft_social_post', 'search_marketing_kb', 'write_knowledge'],
};

export const seoAnalyst: AgentProfile = {
  // ...same as step 3
  allowedTools: ['competitor_lookup', 'search_marketing_kb'],
};
```

```ts src/engine.ts (excerpt) {3}
import { searchMarketingKb, writeKnowledge } from './knowledge';

tools: [draftSocialPost, competitorLookup, schedulePost, searchMarketingKb, writeKnowledge],
```

`write_knowledge`'s real input shape is `{ title, content, tags?, description?, related_notes? }` — see [agent-enterprise § Closing the loop](/packages/agent-enterprise#closing-the-loop-write_knowledge) for the exact fields; it writes a new `.md` note into the vault, not into a specific folder you choose per-call.
