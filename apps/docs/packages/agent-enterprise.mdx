## `createEnterpriseSetup`

```ts
import { createEnterpriseSetup } from '@backendkit-labs/agent-enterprise';
import { ProviderRegistry } from '@backendkit-labs/agent-core';
import { AgentServer } from '@backendkit-labs/agent-web';

const providers = new ProviderRegistry();
providers.register('openai', myOpenAIProvider);

const enterprise = createEnterpriseSetup({
  vaultPath: '/shared/obsidian-vault',
  providers,
  defaultProvider: 'openai',
});

await enterprise.indexAll();

const server = new AgentServer({ port: 3000, engineFactory: enterprise.engineFactory, cors: '*' });
await server.start();
```

`engineFactory` builds through `createBaseEngine` — the same canonical assembly path as `agent-coding` — so an enterprise deployment gets the same MCP/observability/agent-discovery wiring as a coding assistant, without either package needing to know about the other.

## Six department profiles, one vault

| Profile | RAG tool | Vault folder | Provider |
|---|---|---|---|
| `general` | `search_knowledge` (whole vault) | `general/` | `defaultProvider` |
| `support` | `search_support_kb` | `soporte/` | `defaultProvider` |
| `hr` | `search_hr_kb` | `rrhh/` | `local` (sensitive) |
| `sales` | `search_sales_kb` | `ventas/` | `defaultProvider` |
| `finance` | `search_finance_kb` | `finanzas/` | `local` (sensitive) |
| `ops` | `search_ops_kb` | `operaciones/` | `defaultProvider` |

Only `hr` and `finance` set `provider: 'local'` on the profile itself — set that up with an Ollama-backed provider registered under the `local` ID so payroll and financial data never has to leave your network. The other four inherit `defaultProvider`.

Each department's RAG tool is scoped to its own vault folder plus a shared `politicas/` folder (indexed by every department, for company-wide policy documents) and `general/`:

```
/obsidian-vault
├── general/        ← every agent can search here
├── politicas/       ← company-wide policies — indexed by all departments
├── soporte/
├── rrhh/            ← local LLM
├── ventas/
├── finanzas/        ← local LLM
└── operaciones/
```

## Closing the loop: `write_knowledge`

Agents with `write_knowledge` in `allowedTools` can persist knowledge back to the vault directly from conversation — not just read from it. `VaultWriter.createTool(agentId)` bakes the calling agent's ID into the tool at registration time (for the audit trail — the note records who wrote it), so the tool itself only takes the note content, not a folder or filename:

```ts
interface WriteKnowledgeInput {
  title: string;
  content: string;              // Markdown body
  tags?: string[];               // e.g. ["función/arquitectura", "stack/typescript"]
  description?: string;          // one-line summary shown in search results
  related_notes?: string[];      // titles of related notes, embedded as context
}
```

```
User: "Document the new API auth pattern we agreed on"
  → write_knowledge({ title: "API Auth Pattern", content: "## Overview\n...", tags: ["función/backend"] })
  → "Knowledge saved to vault: api-auth-pattern.md"
```

## Embedders

`SimpleEmbedder` (default) is deterministic and hash-based — zero external dependencies, works air-gapped, lower semantic accuracy. `OllamaEmbedder` uses a local Ollama model (`nomic-embed-text` or `mxbai-embed-large`) for real semantic search. Bring your own by implementing `Embedder`'s single `embed(texts: string[]): Promise<number[][]>` method — OpenAI, Cohere, whatever you already run.

## Adding a custom profile

```ts
createEnterpriseSetup({
  ...opts,
  extraProfiles: [{
    id: 'legal',
    name: 'Legal Advisor',
    icon: '⚖️',
    description: 'Legal and compliance specialist',
    systemPrompt: 'You are a legal knowledge assistant...',
    allowedTools: ['search_knowledge', 'write_knowledge'],
    provider: 'local',
  }],
});
```
